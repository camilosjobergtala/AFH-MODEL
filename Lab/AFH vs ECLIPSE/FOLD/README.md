# FOLD — NIVEL 0–4 test ladder

Each `NIVEL <n>` folder is one stage of an increasingly complex falsification test, run in
sequence (NIVEL 0 = simplest check, NIVEL 4 = most complete). Source scripts and their generated
run outputs are kept side by side within each folder.

## NIVEL 0 FOLD/

`FOLD ECLIPSE.py` — ΔtFold test on Sleep-EDF data, based on ECLIPSE v2.0. `eclipse_v2/` holds its
run outputs (JSON reports, EIS report, HTML report) — outputs only, no duplicated source.

## NIVEL 1 PAC/ and NIVEL 2 PAC/

`PAC AFH NIVEL 1.py` and `PAC AFH NIVEL 2.py` (internally labeled "NIVEL 3b OPTIMIZADO... VERSIÓN
RÁPIDA" in its header — a filename/header mismatch worth knowing about if you're looking for
"NIVEL 2" logic and it doesn't match) run the theta-gamma PAC test against ECLIPSE v3.0.

**`eclipse_v3.py` in both folders is byte-identical** (same framework copy, pasted into each
experiment folder so it's self-contained and independently reproducible). This is intentional
duplication, not an accidental copy — kept as-is.

## NIVEL 3 PAC/

An exploratory chain looking for H* → PAC precedence, in this order:

`OJITO.py` (extracts features directly from EDF) → `hctsa discovery.py` (data-driven feature
discovery; finds Hjorth/DFA proxies) → `HCTSA 2.py` (v2.0, uses the discovered proxies) →
`HCTSA 3.py` (v3, more feature combinations + subgroup analysis) → `OJITO_2.py` (renamed from
`OJITO 2`, which had no file extension despite being real Python code; "NIVEL 3b-HCTSA," a
parallel/later branch using catch22/tsfresh instead of HCTSA).

`ONLY N3.py` is a **0-byte empty file** — kept as-is per the archive convention rather than
deleted.

`nivel3b_v3_optimization/` holds the JSON summary + 3 CSVs generated by the `HCTSA 3.py` run.

## NIVEL 4/

A numbered version chain confirmed from each file's own header:

- `1.py` = ECLIPSE v4.2
- `2.py` = v4.3 (fixes over v4.2)
- `3.py` = v4.4 (H* v2 validation)
- `4.py` = v4.5, "FULL DATASET" — **most current** in this chain

`5.py` and `f.py` are **not** part of that chain despite the generic numeric-style names: `5.py`
is a small file-pairing utility, `f.py` is a one-off causality/Granger analysis tool.

`CASCADA.py` → `CASCADA 2.py` → `CASCADA 3.py` → `CASCADA 4.py` is a separate sub-lineage.
`CASCADA.py`/`CASCADA 2.py` differ only by a small window-size fix; `CASCADA 3.py` switches to a
heuristic Lempel-Ziv approach instead of the canonical one; `CASCADA 4.py` (v3.6, "DURATION FIX")
is **most current**.

## figures.py / figures/

`figures.py` (top of `FOLD/`) generates the 4 PDF+PNG figure pairs in `figures/`
(`decision_tree`, `level2_pac_results`, `power_curves`, `stds_distribution`). Note: `NEW/` also
has a file named `figures.py` — **it is unrelated content**, not a duplicate of this one (name
collision only; don't diff/merge them).
